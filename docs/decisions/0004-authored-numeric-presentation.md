# 0004 — Authored numerical presentation

**Status:** accepted direction, 2026-10-20; [plan 0010](../plans/0010-authored-numeric-replies.md).

## Context and options

Local-model rephrasing still fabricated quantities and triggered conservative lexical rejections after canonical-only inputs and exact-number validation fixes. The bounded check accepted no disk phrasings. Further prompt loops, a different model, or authored presentation were possible; the immediate priority is reliable, personalized terminal tool results.

## Decision and approval

The user approved authored character templates for numerical results with “That sounds good, go ahead.” Disk and uptime will provide display-ready fields in the common result. Profile files provide capability-keyed templates; core performs only literal substitution. Missing or invalid presentation returns the exact direct fallback. No model is called for explicit authored replies, including cleanup requests that could load an unused model.

Other results retain the generated canonical-text path. The full canonical result and structured data remain available, so future multi-tool answer composition can consume module-provided facts without requiring this presentation layer to recalculate them. Such composition is future scope, not part of this decision's implementation authorization.

## Consequences

Numerical replies become deterministic and customizable without inference latency. Modules own formatting and units; core still has no domain-specific branches. Authored template prose is trusted local presentation, not a generated claim verified by the LLM guard. The renderer validates syntax and copies values literally, but cannot prove that arbitrary user-authored wording describes them honestly. No expression engine, general template dependency, or automatic model fallback is needed.
