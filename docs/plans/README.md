# Execution plans

Before implementation, write a numbered, scoped plan recording explicit user authorization. Existing explicit authorization for that scope suffices; do not request duplicate confirmation. Ask for approval when authority is missing or scope materially changes. An idea or discussion alone is not approval. Include:

- Objective, scope, non-goals, and approval evidence.
- Acceptance criteria and verification approach.
- Risks, open decisions, and escalation needs.
- Requested role, model, and reasoning effort; observed runtime selection or an explicit unverified status.
- Results, verification evidence, review findings, correction rounds, and final review status.

Keep plans proportional to the work. Do not create product execution plans until their scope is approved. `0001-foundation.md` covers only the approved documentation and agent configuration task.
